01

Watch folders

Add download, staging or network folders. ParForge scans quietly in the background and finds repairable sets.

02

Wait until stable

It does not jump on half-written files. A configurable settle timer waits until the set has stopped changing.

03

Repair with PAR2

ParForge downloads the current official par2cmdline engine and invokes it locally. Your files never leave your PC.

04

Extract with 7-Zip

If 7-Zip is installed, repaired RAR sets are extracted automatically. You can point ParForge at a custom 7z.exe too.

05

Safe by default

The beta never deletes source archives or parity files. Destructive cleanup can wait until the workflow has earned trust.

06

Modern Windows UI

A simple queue, tool status, watch-folder management and readable history instead of decades-old dialogs.

WHY THIS EXISTS

Par-N-Rar stopped at v1.3 in 2008.

PAR2 did not disappear. Neither did multi-part archives, NAS folders, automation or people who want a folder watched and cleaned up without babysitting three different tools. MultiPar is actively maintained and excellent for hands-on PAR work; ParForge is aimed at the separate hands-off workflow: detect → wait → repair → extract.

FAQ

Before you install it

Is ParForge affiliated with Par-N-Rar?

No. ParForge is an independent clean-room product inspired by the useful workflow that older software popularised. It does not use Par-N-Rar code or branding.

Does it upload my archives?

No. Processing is local. ParForge contacts GitHub only to fetch the official par2cmdline Windows binary when that engine is first needed.

Why does Windows show a SmartScreen warning?

The beta is currently unsigned. Code-signing certificates cost money and this experiment is intentionally running at zero upfront cost. Verify the release source and build it yourself if you prefer.

Do I need 7-Zip?

Only for automatic RAR extraction. PAR2 verification and repair work independently. ParForge auto-detects standard 7-Zip installs or lets you choose 7z.exe.

Will it delete the RAR/PAR files?

Not in v0.1. The beta keeps source files after successful processing. Cleanup rules will only be added after the core pipeline is proven.
